Dlaczego branża tego potrzebowała

Płacimy także za niewykorzystane zasoby

Serwer fizyczny

Kupowany pod obciążenie szczytowe. Przez większość czasu część CPU i RAM pozostaje niewykorzystana.

Maszyna wirtualna

Lepsza konsolidacja, ale każda VM utrzymuje własny system operacyjny i rezerwuje zasoby.

Kontener

Wspólne jądro oznacza mniejszy narzut, większą gęstość usług i szybsze skalowanie.

Koszt to nie tylko zakup serwera: energia, chłodzenie, miejsce, licencje, utrzymanie i czas administratorów.

Jądro Linuksa / 03

Warstwy są współdzielone

Obraz to stos niezmiennych warstw. Dwa kontenery uruchomione z tego samego obrazu współdzielą warstwy obrazu, ale każdy otrzymuje własną cienką warstwę zapisu.

Zmiana pliku nie modyfikuje obrazu. Mechanizm copy-on-write kopiuje zmieniany plik do warstwy kontenera.

warstwa kontenera
zapis / copy-on-write
kod aplikacji
tylko odczyt
biblioteki i runtime
tylko odczyt, współdzielone
bazowy system plików
tylko odczyt, współdzielony
jądro hosta — poza obrazem

Wielostopniowe budowanie

Narzędzia budujące nie muszą trafić do wyniku

FROM maven:3-eclipse-temurin-21 AS build
WORKDIR /src
COPY . .
RUN mvn -q -DskipTests package

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /src/target/*.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]

Źródła obrazów: maven — etap budowania · eclipse-temurin — mały obraz uruchomieniowy.

Container

Instancja obrazu w ruchu

Kontener ma własną konfigurację, sieć i warstwę zapisu. Usunięcie kontenera usuwa tę warstwę — dane trwałe wymagają wolumenu.

Uruchomienie

docker run łączy kilka operacji

docker run -d --name space-api \
  -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=docker \
  space-api:1.0

-d tło · --name nazwa · -p port · -e zmienna

DEMO NA ŻYWOUruchom API, sprawdź ps, logi oraz endpoint HTTP.
Sieć

Port hosta ≠ port kontenera

localhost:8088
host
-p 8088:8080

proces

EXPOSE dokumentuje port. Dopiero -p udostępnia go hostowi.

DEMO NA ŻYWOUruchom ten sam obraz z innym portem hosta i porównaj adresy.
Komunikacja

W jednej sieci używamy nazw

docker network create mission-net
docker run --network mission-net --name db mysql:8
docker run --network mission-net --name api space-api

API łączy się z db:3306, nie z localhost:3306.

DEMO NA ŻYWOPokaż błąd z localhost, potem wspólną sieć i rozwiązywanie nazwy db.
Dane trwałe

Named volume żyje niezależnie od kontenera

docker volume create mysql-data

docker run --name db \
  -v mysql-data:/var/lib/mysql \
  mysql:8
  • mysql-data — nazwa nadana przez nas,
  • /var/lib/mysql — miejsce danych wewnątrz kontenera,
  • Docker wybiera fizyczną lokalizację na hoście,
  • usunięcie kontenera nie usuwa named volume,
  • nowy kontener może podłączyć ten sam wolumen.

Named volume wybieramy dla danych aplikacji. Bind mount jest wygodniejszy, gdy człowiek ma edytować pliki z hosta, np. kod źródłowy.

Named volume / cykl życia

Kontener można wymienić bez utraty bazy

kontener DB v1

Konfiguracja

Nie wszystko powinno być w obrazie

  • ustawienia przekazujemy przy uruchomieniu,
  • sekretów nie commitujemy do repozytorium,
  • sieć domyślna daje DNS po nazwie usługi,
  • wolumen oddziela cykl życia danych od kontenera.
Gotowość

Uruchomiony proces nie zawsze jest gotowy

  test: ["CMD-SHELL", "pg_isready -U app"]
  interval: 5s
  timeout: 3s
  retries: 10

  db:

Bezpieczeństwo

Najczęstsze zagrożenia

  • niezaufane lub stare obrazy,
  • sekrety w warstwach obrazu,
  • proces działający jako root,
  • nadmiar capabilities.
  • montowanie socketu Dockera,
  • publiczne porty bazy,
  • brak limitów zasobów,
  • podatne zależności.
Checklista

Buduj mniejszą powierzchnię ataku

  • używaj minimalnych, oficjalnych obrazów i przypinaj wersje,
  • uruchamiaj proces jako użytkownik bez uprawnień root,
  • nie zapisuj sekretów w Dockerfile ani repozytorium,
  • skanuj obrazy i regularnie je przebudowuj,
  • publikuj tylko potrzebne porty.
