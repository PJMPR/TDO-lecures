Rozwiązanie

Deklaracja

Repozytorium opisuje oczekiwany stan.

Automatyzacja

Moduły wykonują potrzebne zmiany.

Weryfikacja

Kolejne uruchomienie ujawnia dryf.

Architektura

Kontroler wysyła zadania do hostów

control node
WSL + Ansible
SSH + Python
lub local
managed node
agent Ubuntu 24.04

Na hoście zarządzanym nie instalujemy demona Ansible. W wariancie WSL kontroler i host to ta sama dystrybucja.

Push model

Ansible nie wymaga własnego agenta

  • kontroler odczytuje inventory i playbook,
  • łączy się przez SSH albo używa połączenia lokalnego,
  • uruchamia moduły przez Python na hoście,
  • zbiera wynik każdego zadania.

GitHub Actions runner jest osobnym agentem wykonawczym. Ansible może go przygotować i zarejestrować.

Pojęcie 02

Playbook opisuje przebieg konfiguracji

- name: Przygotuj agentów budujących
  hosts: build_agents

Pojęcie 03

Task wywołuje moduł z argumentami

- name: Zainstaluj pakiety bazowe
  ansible.builtin.apt:
    name:
      - git
      - unzip
    state: present
    update_cache: true

apt zna stan pakietów. Surowa komenda nie daje tej samej gwarancji.

Raport

Każde zadanie kończy się stanem

ok

Stan już był poprawny.

changed

Moduł wykonał zmianę.

failed

Play zatrzymał się lub obsłużył błąd.

Ansible Vault

Szyfruje pliki zmiennych przechowywane w repozytorium.

ansible-vault create group_vars/vault.yml
ansible-playbook site.yml --ask-vault-pass

Token runnera

GitHub generuje krótkotrwały token rejestracyjny. Przekazujemy go tylko podczas rejestracji.

Bezpieczna próba

Check mode przewiduje część zmian

ansible-playbook playbooks/agent.yml --check --diff

Nie każdy moduł potrafi wiernie symulować zmianę. Check mode nie zastępuje testu na świeżej maszynie.

03
Repozytorium

Projekt startowy

cd projects/ansible-agent-starter
cp inventories/local.example.yml inventories/local.yml

Starter zawiera strukturę i kryteria, ale zadania ról pozostają do uzupełnienia.

04
Pierwszy kontakt

Ping lokalnego hosta

ansible build_agents -m ansible.builtin.ping
ansible build_agents -m ansible.builtin.setup \
  -a 'filter=ansible_distribution*'

ping sprawdza wykonanie modułu przez Python, a nie ICMP.

05
Rola common

Pakiety bazowe i użytkownik roboczy

- name: Zainstaluj narzędzia bazowe
  ansible.builtin.apt:
    name: "{{ common_packages }}"
    state: present
    update_cache: true

Lista obejmuje Git, curl, GPG, unzip, tar i certyfikaty CA.

06
Rola dotnet

.NET SDK z repozytorium Ubuntu

- name: Zainstaluj .NET SDK
  ansible.builtin.apt:
    name: "{{ dotnet_sdk_package }}"
    state: present

Ubuntu 24.04 publikuje pakiety .NET. Nie mieszamy ich z repozytorium Microsoft.

07
Rola node

Node.js z weryfikacją SHA-256

- name: Pobierz archiwum Node.js
  ansible.builtin.get_url:
    url: "{{ node_download_url }}"
    dest: "{{ node_archive_path }}"
    checksum: "sha256:{{ node_sha256 }}"

Przypięta wersja i suma kontrolna dają ten sam artefakt przy każdym uruchomieniu.

08
Rola node

Angular CLI jako jawna wersja

- name: Zainstaluj Angular CLI
  community.general.npm:
    name: "@angular/cli"
    version: "{{ angular_cli_version }}"
    global: true

W projekcie produkcyjnym preferujemy lokalny CLI i npm ci. Globalny CLI służy tu do diagnostyki agenta.

09
Rola terraform

Podpisane repozytorium HashiCorp

- name: Dodaj repozytorium HashiCorp
  ansible.builtin.deb822_repository:
    name: hashicorp
    uris: https://apt.releases.hashicorp.com
    suites: noble
    components: main
    signed_by: /usr/share/keyrings/hashicorp.asc

Próba agenta

Cztery małe buildy

./scripts/verify-toolchains.sh

Dla publicznego repozytorium kod z forka może być niebezpieczny dla trwałego self-hosted runnera. Laboratorium używa prywatnego repozytorium albo świadomie izolowanego hosta.

WSL

Usługa runnera wymaga działającego WSL

Test interaktywny

Uruchom ./run.sh w otwartym terminalu WSL.

Usługa systemd

Włącz systemd w WSL, zrestartuj dystrybucję i dopiero użyj svc.sh.

Zamknięcie WSL lub uśpienie Windows zatrzymuje dostępność runnera.

GitHub Actions

Workflow wybiera etykiety agenta

jobs:
  build:
    runs-on: [self-hosted, linux, x64, tdo-build]
    steps:
      - uses: actions/checkout@v4
      - run: dotnet build
      - run: npm ci && npm run build
        working-directory: frontend
      - run: terraform fmt -check -recursive
Gdy nie działa

Diagnostyka od połączenia do zadania

  1. ansible-inventory --graph — czy host istnieje?
  2. ansible build_agents -m ping -vvv — czy działa transport i Python?
  3. --check --diff — co Ansible chce zmienić?
  4. --start-at-task i --tags — gdzie wznowić?
